# Self-serve 3.0: минимальный, через Telegram (без веб-кабинета)

## Что реализовано в 3.0
Полный веб-кабинет сознательно не входит в запуск (см. NOT-цели 3.0).
Self-serve реализован ботом:

| Потребность | Как |
|---|---|
| Зарегистрироваться | `/start` в личке: создаётся `customers` + личный API-ключ |
| Увидеть баланс | `/balance` — баланс и доступный (с учётом активных холдов) |
| Узнать ключ | `/key` — только префикс; сырой ключ не выдаётся повторно |
| Новый ключ | `/rotate` — старый отзывается, новый показывается один раз, событие в `admin_audit_logs` (actor=customer:<id>) |
| Купить кредиты | `/buy` → инвойс Telegram Stars → `/successful_payment` (см. docs/PAYMENTS.md) |
| Использовать | тот же ключ в REST API (`X-API-Key`); бот-трансформации тоже списывают личный баланс |

## Безопасность ключей
- Сырой ключ показывается ровно один раз (создание/ротация), не логируется,
  не отправляется в группы; повторный запрос → только префикс + `/rotate`.
- Ротация деактивирует старый ключ немедленно.
- Ключи клиентов создаются со скоупами `transform, usage.read`.

## Доступ
- `TELEGRAM_PUBLIC_MODE=false` (по умолчанию): self-serve-команды в личных
  чатах доступны всем; хаос-обработка (тексты/документы) — только
  админам/allow-list. Публичный демо-режим — `true` (лимиты+предупреждение).
- Покупки — только в личных сообщениях; группы получают отказ.

## Что осталось на 2.1+ (веб-кабинет)
- Jinja2-страницы `/web`, регистрация по e-mail, сессии в БД, CSRF,
  организации/роли (таблицы уже в миграции 0002; скоупы enforced).
- Свои дополнительные ключи помимо основного (админ может создать через
  `/admin/api-keys` с `customer_id` вручную).
