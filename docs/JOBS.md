# Асинхронные задачи и батчи (JOBS_ENABLED=false по умолчанию)

## Включение
```env
JOBS_ENABLED=true
JOB_INPUT_RETENTION_HOURS=24
BATCH_INLINE_LIMIT=5
BATCH_MAX_ITEMS=100
# при REDIS_URL очередь через Redis (LPUSH/BRPOP), иначе asyncio.Queue
```

## Эндпоинты
- `POST /v1/jobs` — `{"items": [{"raw_text": "...", "schema_preset": "..."}]}`
  (или одиночный `{"raw_text": ...}`) → 202 + job.
- `GET /v1/jobs/{id}` — статус, прогресс, результаты по элементам.
- `POST /v1/jobs/{id}/cancel` — отмена (pending/running; между элементами).
- `POST /v1/transform/batch` — до `BATCH_INLINE_LIMIT` элементов
  обрабатывается синхронно (частичные результаты: `completed`/`failed` по
  каждому); больше — автоматически создаётся задача (иначе 422 с
  подсказкой).

## Статусы
Задача: `pending → running → completed | failed | canceled`.
Элемент: `pending → running → completed | failed | canceled`.
Частичный успех: задача `completed`, если есть хоть один успех; `failed` —
только если провалились все.

## Хранение данных (важное отличие от синхронного режима)
- Синхронные `/v1/transform*`: сырые входы не сохраняются вообще.
- Задачи: входы лежат в `jobs.input` пока задача в очереди/выполняется;
  **удаляются немедленно после завершения** (успех/провал/отмена).
- Защитный TTL `JOB_INPUT_RETENTION_HOURS` чистит входы упавших/зависших
  задач (фоновый цикл раз в 5 минут, `purge_expired_inputs`).
- Результаты (`job_items.result`) сохраняются для выдачи клиенту.

## Очередь и воркер
- Очередь: `InProcessQueue` (один процесс — разработка) или `RedisJobQueue`
  (`REDIS_URL`). Воркер — фоновая задача процесса API: достаёт job_id,
  выполняет элементы последовательно, эмитит `job.completed`/`job.failed`.
- Один consumer на процесс. Горизонтальное масштабирование воркеров —
  docs/ROADMAP.md (вынос в отдельный сервис `worker`).
- Каждая трансформация элемента проходит полный биллинговый контур
  (холды, лимиты, автопочинка) как синхронный запрос.

## Тесты без очереди/сети
`tests/test_jobs.py`: создание, выполнение (тот же код, что и воркер),
отмена, доступ владельца, батч с частичной ошибкой, авто-задача при
большом батче, удаление входов (retention 0), FIFO-очередь, живой воркер
со stop_event.
