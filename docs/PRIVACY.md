# Приватность Perfect JSON API

## Какие данные обрабатываются
- Текст/файлы, присланные для трансформации (содержимое клиентов).
- API-ключи (только хэши), метаданные использования (объёмы, коды ошибок,
  стоимости), настройки Telegram-чатов (пресет, custom schema, счётчики).
- Платежи: суммы, провайдер (Telegram Stars), идентификаторы чеков;
  карточные/платёжные данные сервис не видит (оплата внутри Telegram).

## Что НЕ сохраняется
- Сырые входные тексты и файлы синхронных запросов — обрабатываются в
  памяти и не пишутся в БД/логи.
- Результаты трансформаций — не сохраняются.
- Тела запросов, схемы и файлы — не логируются.

## Что сохраняется временно
- `jobs.input` (входы асинхронных задач): удаляются сразу после завершения
  задачи; защитный TTL `JOB_INPUT_RETENTION_HOURS` (по умолчанию 24 ч) для
  упавших/зависших задач. В `jobs.output` остаются только результаты.
- `idempotency_keys.response_body`: закэшированный ответ для повторов
  (содержит результат трансформации) — очищается по политике оператора.

## Логи
- Формат: метод, путь, статус, длительность, request_id, префикс ключа.
- Без тел, файлов, схем, результатов, секретов.

## Права субъектов (GDPR-ориентир)
- Удаление по запросу: `DELETE FROM api_keys WHERE id=...` (каскад удаляет
  usage_logs, транзакции, вебхуки, задачи ключа).
- Экспорт по ключу: `GET /v1/usage` + `GET /admin/usage?key_id=`.
- Хранение: пока активен аккаунт ключа; бэкапы — см. docs/OPERATIONS.md.

## Sub-processors
- LLM-провайдер (передаётся текст запроса; выбор провайдера — за
  оператором, BYO-ключ в планах).
- Опционально: Redis (только счётчики/очереди, без содержимого),
  ClamAV-совместимый сканер (файл целиком, `MALWARE_SCAN_ENABLED`).
