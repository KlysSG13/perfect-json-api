# Безопасность Perfect JSON API

## Аутентификация
- Пользовательские ключи `pj_...`: сырой ключ показывается один раз, в БД —
  SHA-256 хэш + префикс; поиск по хэшу; неактивный ключ → 403.
- Админ-ключ: `X-Admin-Key`, сравнение `secrets.compare_digest`; пустой
  `ADMIN_API_KEY` полностью отключает админ-API (401).
- Скоупы ключей (`scopes`): `transform`, `usage.read`, `keys.read`,
  `keys.write`, `billing.read`, `billing.write` — проверяются только если
  ключ имеет явные скоупы; нарушение → 403 `forbidden_scope`.

## Секреты
- Только переменные окружения; `.env` в `.gitignore` и `.dockerignore`.
- В логах нет секретов, тел запросов, файлов, схем и результатов
  (проверяется тестом `test_no_secrets_in_any_response`).
- В production при старте: отсутствие `SECRET_KEY`/`ADMIN_API_KEY` или
  SQLite → отказ запуска; отсутствие `REDIS_URL` → предупреждение.

## Защита от злоупотреблений
- Rate limits: rpm/rpd на ключ (пер-ключевые переопределения), на админа;
  429 с `Retry-After`/`X-RateLimit-*`; Redis при `REDIS_URL`, иначе
  in-memory (один процесс).
- Дневные/месячные лимиты трат и пер-запросный кап стоимости.
- Лимит конкурентных трансформаций на ключ.
- Telegram: `TELEGRAM_PUBLIC_MODE=false` по умолчанию (только админы и
  allow-list), антифлуд сообщений/минуту, дневной лимит на чат.

## Файлы
- Проверка magic bytes: расширение обязано совпадать с реальным типом
  (`.pdf` = `%PDF-`, `.docx` = ZIP с `word/`, картинки/аудио по сигнатурам);
  бинарник под видом текста → 415 `invalid_file_content`.
- Структурные лимиты: `MAX_PDF_PAGES`, `MAX_DOCX_PARAGRAPHS`, `MAX_CSV_ROWS`,
  `MAX_JSON_DEPTH`, `MAX_JSON_KEYS`, `MAX_EXTRACTED_CHARS` (обрезка с
  предупреждением в `meta.warnings`).
- Антивирус: `MALWARE_SCAN_ENABLED` + `CLAMAV_URL` (REST ClamAV); сканер
  недоступен → 503 `malware_scanner_unavailable`, файл не обрабатывается.

## Prompt injection
- Системный промпт v2 объявляет пользовательский текст данными,
  инструкции внутри него игнорируются; выдача секретов/системного промпта
  запрещена. Тесты: `tests/test_prompt_injection.py`.
- Пользовательские JSON Schema проверяются до LLM: запрет удалённых `$ref`,
  паттернов >512 символов (ReDoS), схем >64 КБ и глубже 64 уровней.

## Данные
- Сырые входы и результаты трансформаций не сохраняются.
- Исключение (явно задокументировано): входы асинхронных задач хранятся в
  `jobs.input` до завершения и удаляются сразу после него; защитный TTL —
  `JOB_INPUT_RETENTION_HOURS` (см. docs/JOBS.md).
- Идемпотентные ключи хранят хэш тела и закэшированный ответ (без сырого
  входа трансформации; сам ответ — данные клиента, TTL не настроен —
  очищайте таблицу по политике).
